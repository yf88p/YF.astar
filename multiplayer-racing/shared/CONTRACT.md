# Shared implementation contract

The wire protocol is `shared/protocol.ts`. Do not rename existing public fields without coordinating.

`shared/tracks.ts` exports `TRACKS: Record<TrackId, Track>`. Track fields: `id`, `name`, `subtitle`, `description`, `difficulty`, `length` (meters), `width` (full road width), `points: {x:number,z:number}[]` (closed circuit sampled centerline, no repeated closing point), `checkpoints: {x:number,z:number,yaw:number}[]` (ordered; index 0 is finish/start). `yaw` is atan2(dx,dz), forward is (sin(yaw), cos(yaw)). Also export `nearestTrack(track,x,z)` returning `{x,z,distance,progress,index,yaw}`, progress is [0,1). Track names: canyon = "Sunset Canyon" (warm red rock, dry grip); harbor = "Neon Harbor" (night industrial docks, slippery tight corners).

`shared/simulation.ts` exports `createCar(id, track, gridIndex, startTick): CarState`, `stepCar(car, controls, track, dt = 1/60): CarState` (pure physics, same client/server), `stepRace(cars, inputs: Record<string,Controls>, track, tick, startTick, laps): CarState[]` (authoritative physics + collisions + checkpoint/lap/finish and reset penalties), `botControls(car,track,tick): Controls`, `rankCars(cars): CarState[]`, `raceResults(cars, players, startTick): RaceResult[]`. All pure, no random/time globals. `CarState.lap` starts at 1; `.checkpoint` is next checkpoint (starts at 1); `finishTick` null until all requested laps complete. `progress` is validated race progress, suitable for rank/minimap, not raw projection. Units meters/seconds; typical max speed ~65m/s. Road length target 1100m canyon / 900m harbor, 16-22m wide, 10-16 checkpoints. start grid behind checkpoint 0 with forward yaw at checkpoint 0. Bot finishing one lap in <120 sec is essential.

Server index exports createGameServer({port,host,seedRooms?,...}) usable in integration tests and starts only when directly invoked. It exposes a `GameServer` with server/ws service/rooms and `close()`. Server snapshots at 20Hz, simulation at 60Hz. Commands generated client at 60Hz, batch up to 6 at 30Hz; ack is last _consumed_ seq per player. Server must consume at most one command per player per physics tick, hold last input max 250ms then neutral. No input clock used for simulation, stale/duplicate ignored. Snapshot ack lets client replay pending predicted inputs. Full snapshots justified by 8-car max. Reconnect token unpredictable, rotated on reconnect; id maintained. Broadcast room list globally when room data changes. `room` messages update player membership/settings; snapshots sent only to members. Initial connection sends hello then server sends welcome plus rooms. Create/join returns room then snapshot. Seed rooms are real joinable lobby rooms with only bots, never fabricated live humans, and can remain until server shutdown.
